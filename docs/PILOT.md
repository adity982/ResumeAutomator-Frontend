# Pilot and demonstration guide

The software supports a pilot; real participants have not been recruited or tested by adding this file.

## Recruit five to ten developers

Choose people who have multiple projects and a real target job. Obtain permission before collecting their feedback or publishing their documents. Ask them to use their own accounts and public repositories they are comfortable importing. Do not collect employer-confidential material.

## Observe one complete task

1. Open the illustrative sample without signing in. Ask the participant to explain what they think the product does.
2. Sign in, add a resume and save one real target job.
3. Import two or three selected public repositories. Watch whether file selection and contribution confirmation make sense without help.
4. Run project selection. Ask why each chosen project fits, and ask the user to inspect the sources.
5. Review the proposed bullets, preview the actual PDF, approve and save a document version.
6. Attach the version to an application, record its stage and save workspace progress.
7. Reload and recover progress. Optionally add a contact and prepare a manual outreach draft.
8. Save pilot feedback in Activity. Ask what was confusing and what they would return to do next week.

Record completion without help, time on task, source relevance disagreements, unsupported claims caught, edits needed and whether the participant voluntarily returns for a second application. Use the feedback form/export with permission. Do not infer interview uplift from resume scores or a handful of anecdotes.

## Demonstration sequence

Use clearly labeled sample data or your own approved public project evidence. Show one job requirement, the selected project, its immutable source, the proposed bullet and the final reviewed document. Include a missing-evidence case. Explain the lexical baseline, learned embeddings, hybrid fusion and why retrieval does not verify authorship.

Publish a benchmark table with dataset size, split, model/version, evaluation command, limitations and a link to the dataset. Dense retrieval may outperform hybrid on a particular dataset; report the actual numbers. Do not invent user counts, time savings, citations, performance improvements or endorsements.

## Public launch gate

Confirm staging and production backend/frontend revisions, PostgreSQL migrations and restore testing, Firebase configuration, worker availability, model warm-up, account deletion/export, mobile usability, privacy/backup retention and provider budgets. Publish known limitations. Private GitHub access requires operator App registration and a live consent test. General LinkedIn people search and automated messaging are not enabled. See PILOT-STUDY.md for consent and observation procedures and LAUNCH-KIT.md for reusable demo and announcement materials.
